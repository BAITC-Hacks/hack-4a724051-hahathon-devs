# API каталога ekt.kz

Дата наблюдений: 2026-09-23. Это описание внешнего API по двум успешным GET-запросам и документу партнёра, не полная официальная спецификация. Обязательность полей и поведение всех ошибок ещё не подтверждены. Собственный API приложения проектируется в [architecture.md](architecture.md).

## Доступ

- Базовый адрес: `https://ekt.kz`.
- Авторизация: HTTP Basic Auth, только по HTTPS.
- Логин: переменная окружения `EKT_API_USER`.
- Пароль: переменная окружения `EKT_API_PASSWORD`.
- Значения хранятся на backend. Браузер обращается к нашему серверу и не получает эти секреты.
- Заголовок `Authorization` и его Base64-представление не записываются в логи.
- Адрес внешнего сервиса фиксирован серверной конфигурацией. Клиент и LLM не передают произвольный URL для запроса. Редиректы с передачей авторизации на другой адрес запрещены.

## GET /api/products

Получение страницы каталога. Первая страница проверена, получен HTTP 200.

| Параметр | Тип | Описание |
| --- | --- | --- |
| `page` | положительное целое | Номер страницы. Пример партнёра: `/api/products?page=2`. Без параметра в проверке вернулась страница 1 |

Размер страницы в наблюдении — 20. Параметр изменения размера страницы не документирован.

### Структура ответа

| Поле | Наблюдаемый тип | Значение |
| --- | --- | --- |
| `page` | integer | Текущая страница |
| `per_page` | integer | Размер страницы, наблюдалось 20 |
| `count` | integer | Наблюдалось 20 при 20 элементах; не считать общим размером каталога |
| `items` | array | Товары страницы |
| `items[].id` | integer | Внутренний ID товара |
| `items[].name` | string | Наименование |
| `items[].article` | string | Внутренний артикул; сохранять ведущие нули и суффиксы |
| `items[].price` | number | Цена; отдельной валюты и явного признака включения НДС не обнаружено |
| `items[].image` | string или null | URL изображения либо отсутствие изображения |
| `items[].url` | string | Ссылка на карточку на сайте |
| `items[].url_api_detail` | string | Адрес детальной карточки API |
| `items[].offers` | array | В проверенной странице пустые массивы; схема непустого массива неизвестна |

Сокращённый пример: показан один элемент из фактически полученных 20, метаданные исходной страницы сохранены.

```json
{
  "page": 1,
  "per_page": 20,
  "count": 20,
  "items": [
    {
      "id": 515279,
      "name": "027004 АВ DRX125 MT 3ф 40А 10ka Legrand (1)",
      "article": "200300273_",
      "price": 26930,
      "image": "https://ekt.kz/upload/iblock/592/ecrd69l3r236hyuttkj4lmnz1euly1a7/027004_av_drx125_mt_3f_40a_10ka_legrand_1.jpg",
      "url": "https://ekt.kz/catalog/nizkovoltnaya_apparatura/silovye_avtomaticheskie_vyklyuchateli/drx125_mt_10_250_a_legrand/027004_av_drx125_mt_3f_40a_10ka_legrand_1/",
      "url_api_detail": "https://ekt.kz/api/products/detail?id=515279",
      "offers": []
    }
  ]

```

В списке нет `description`, `quantity`, `stores`, `properties` и отдельного поля категории. Отсутствие остатка в списке не означает нулевой остаток.

### Пагинация и синхронизация

`total`, `total_pages`, `next`, курсор и API изменений в проверенном ответе отсутствуют. До уточнения контракта синхронизатор последовательно читает страницы с защитой от повторяющейся страницы, пределом количества запросов и общим дедлайном. Пустая страница — кандидат на конец обхода, но поведение последней страницы следует проверить на интеграции. Короткую страницу не считать безусловным доказательством конца без подтверждения партнёра.

Оборванный импорт получает статус `partial`. Он не удаляет предыдущие товары и не позволяет говорить «товара нет во всём каталоге». Состояние `complete` выставляется только при подтверждённой полноте. Первое демо может использовать явно обозначенную выборку.

## GET /api/products/detail

| Параметр | Тип | Описание |
| --- | --- | --- |
| `id` | положительное целое | Внутренний ID, не артикул. Проверен `515291` |

### Структура ответа

| Поле | Наблюдаемый тип | Значение |
| --- | --- | --- |
| `id`, `name`, `article`, `price`, `image`, `url`, `offers` | как в списке | Данные товара; непустые offers не исследованы |
| `description` | string | Описание и технические характеристики свободным текстом, с переводами строк |
| `quantity` | number | Общий остаток из источника |
| `stores` | array | Остатки по складам |
| `stores[].id` | integer | ID склада |
| `stores[].name` | string | Название склада; может быть внутренним |

| `properties` | object | Неоднородный словарь свойств: встречаются строки и массивы строк |

## Правила преобразования в нашу модель

### Категорию берём из url

В MVP получаем путь категории из `url`: проверяем HTTPS и host `ekt.kz`, разбираем путь после `/catalog/`, исключаем последний сегмент — slug товара. Например:

```text
/catalog/nizkovoltnaya_apparatura/silovye_avtomaticheskie_vyklyuchateli/drx250_mt_10_250_a_legrand/<product>/
→ [nizkovoltnaya_apparatura, silovye_avtomaticheskie_vyklyuchateli, drx250_mt_10_250_a_legrand]
```

Храним `category_path` и `category_source=url`. Это выведенная классификация, а не подтверждённый ID категории. Акционные разделы могут отражать маркетинговую подборку. При неожиданной структуре — `category_path=null` и предупреждение. Читаемое имя категории задаёт отдельный проверенный словарь; не выдумываем его из транслитерации.

### Характеристики берём из description и сверяем

Основной текстовый источник характеристик — `description`. Парсер выделяет известные параметры категории и единицы измерения; хранит исходный фрагмент и извлечённое значение. `name` и `properties` используются для перекрёстной проверки и дополнения с отдельным происхождением. Приоритет description не означает, что он всегда верен.

Реальный конфликт: в названии и полном описании 515291 указан ток 160 А, в `properties.NOMINALNYY_TOK` — 250 А. Результат для критичного параметра:

```json
{
  "key": "rated_current",
  "value": null,
  "unit": "A",
  "status": "conflict",
  "observations": [
    {"source": "description", "value": "160"},
    {"source": "properties.NOMINALNYY_TOK", "value": "250"}
  ]
}
```

Такой товар не проходит автоматическую проверку совместимости по спорному параметру. Название серии `DRX250` тоже нельзя интерпретировать как номинальный ток устройства.

### Цена, остатки, идентификаторы

- Деньги и количества внутри backend — Decimal; в собственном JSON денежные суммы — десятичные строки. Валюту подтверждает владелец каталога.
- `id`, внутренний `article`, артикул поставщика и штрихкод — отдельные поля. Поиск может иметь дополнительные нормализованные ключи, но оригиналы сохраняются неизменно.
- `quantity=0`, отсутствие quantity и недоступность API — разные состояния.
- Склады для продажи и резервирование должны быть подтверждены партнёром. В источнике есть брак, образцы и перемещение; общий остаток пока нельзя считать гарантированно доступным к продаже.
- `KRATNOST_MIN` похоже на кратность/минимум, но точная семантика не документирована. Не применять догадку как правило заказа.
- `RECOMMEND` — не подтверждённая таблица аналогов. `offers=[]` не означает отсутствие товара.
- Время нашего получения (`fetched_at`) известно; время последнего изменения у владельца (`source_updated_at`) неизвестно. Свежий HTTP-ответ не доказывает свежесть учётной системы.
- Поле сертификата в проверенной карточке не обнаружено. Возвращаем неизвестность, пока не предоставлен реальный источник; не конструируем ссылки на сертификаты.

## API корзины нет в предоставленном контракте

Даны только операции чтения каталога. Endpoint добавления в корзину, cookie/токен покупателя, резерв, идемпотентность и ссылка на checkout не предоставлены. Наличие таких механизмов на самом сайте не проверено.

Поэтому в архитектуре:

- `EktCatalogAdapter` читает реальный каталог.
- `DemoCartAdapter` работает с собственной явно обозначенной демонстрационной корзиной.
- `EktCartAdapter` имеет статус `requires_integration`; реальное добавление недоступно до получения контракта и прохождения проверок.
- Ссылка демо ведёт на наш `/cart`; она не выдаётся за корзину ekt.kz.

## Ошибки и защитные пределы адаптера

Это предлагаемые правила нашего клиента, а не обещания поведения EKT:

| Ситуация | Наше действие |
| --- | --- |
| 401/403 | Ошибка конфигурации доступа; без повторов, без показа секретов клиенту |
| 404 | Сначала проверить контракт ошибки; товар считать отсутствующим только по подтверждённому ответу |
| 429 | Ограниченный повтор GET с учётом Retry-After и общего дедлайна |
| Timeout/5xx | До одного повтора GET с jitter в пределах дедлайна; затем unavailable, без подмены нулевым остатком |
| 200 с невалидным JSON/полями | `upstream_schema_error`, метрика, запрет зависимого действия |
| Слишком большой ответ | Прервать поток по лимиту байтов, сообщить об отказе |
| Частичная синхронизация | Сохранить последнюю пригодную версию индекса; пометить покрытие как частичное |

На запуске: connection timeout 2 с, общий deadline интерактивного GET 5 с, не более двух одновременных запросов к EKT на экземпляр. Это стартовые настройки для измерений; глобальный предел согласовать до горизонтального масштабирования. Проверка TLS включена.
