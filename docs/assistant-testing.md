# Ассистент: запуск, проверка и границы готовности

Актуальный HTTP runtime: `backend/app/modules/assistant/runtime.py`. Это основной путь API → очередь → worker → OpenAI-план → серверный ответ. Старый доменный Anthropic runner сохранён для совместимости, но не подключён к HTTP runtime. Этот документ заменяет прежние утверждения о полной блокировке LLM в документации первого этапа.

## Куда положить ключ

Локальный файл **`D:/hack-4a724051-hahathon-devs/.env`**, рядом с README, а не в frontend. Создан шаблон с пустыми секретами; `.env` исключён из Git. Не отправляйте ключ в чат и не добавляйте `NEXT_PUBLIC_`.

Для теста OpenAI измените локально:

```dotenv
LLM_API_KEY=ваш_ключ_OpenAI
LLM_PROVIDER=openai
LLM_MODEL=gpt-4.1-mini
LLM_ALLOWED_MODELS=["gpt-4.1-mini"]
LLM_ENABLED=true
LLM_DATA_POLICY_ACCEPTED=true
INTEGRATION_MODE=synthetic
```

`LLM_DATA_POLICY_ACCEPTED=true` означает, что оператор разрешил передачу текста запросов и ограниченного контекста OpenAI. Вложения передаются только при дополнительном `allow_external_analysis=true` в запросе клиента. `store=false` в Responses API отключает сохранение response для дальнейшего API-чтения; это не обещание отсутствия любой обработки или хранения у провайдера.

Без ключа оставьте `LLM_ENABLED=false`: работают поиск, карточки, условия покупки, аналоги и подтверждение демо-корзины по шаблонам. Свободное распознавание намерения, фото и сканы требуют включённой модели. Наличие ключа само по себе ничего не включает.

API и worker читают один корневой `.env`. После изменения настроек перезапустите оба процесса. Не включайте `APP_ENV=production`: публичное развёртывание ещё требует PostgreSQL, проверки инфраструктуры и интеграции реальных источников.

## Запуск

Из backend установите зависимости: `.venv/Scripts/python.exe -m pip install -r requirements.lock -e ".[dev]"`.

В одном терминале: `.venv/Scripts/python.exe -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000 --no-proxy-headers`.

Во втором: `.venv/Scripts/python.exe -m app.worker`.

Документация HTTP: `http://127.0.0.1:8000/docs`. Все запросы изменения требуют разрешённый Origin, cookie и X-CSRF-Token; создание сессии требует Origin. Проверять удобно из клиента на localhost:3000 или локального скрипта с cookie jar. Схема — `docs/openapi.json`.

## Что возвращает чат

`AssistantOutput` дополнен `language`, `proposal`, `sources`, `alternative_reasons`, `warnings`. Карточки содержат `certificates`, `unit`, `min_order`. Существующие поля сохранены. `mode=grounded` означает план от модели и ответ из серверных фактов; это не свободный текст модели.

Последовательность: POST session → POST conversations → POST conversations/{id}/turns → GET turns/{id} до completed. Для отправки нужен уникальный Idempotency-Key; повтор с тем же телом и ключом возвращает прежний turn.

```json
{
  "text": "Купить 990100003_ 2 шт",
  "language": "auto",
  "asset_ids": [],
  "allow_external_analysis": false
}
```

Корзина после этого не меняется. Ответ содержит состав и сумму proposal. Отдельное сообщение `да, добавь` / `иә, қос` / `yes, add` подтверждает только предложение из последнего завершённого ответа **этого диалога**. Кнопка подтверждения использует POST proposals/{id}/confirm с `{version}`. Сервер повторно проверяет владельца, TTL, версию, цену и остаток. Текст из файла и решение модели подтверждением не являются.

Ссылка после успешного добавления: `/api/v1/cart/view`. Она отображает актуальную корзину текущей cookie-сессии. Это демонстрационная корзина, без оплаты и оформления реального заказа. Сертификаты демо доступны по `/api/v1/certificates/SYN-<id>.pdf`; файлы помечены синтетическими в исходных данных.

Отмена turn прекращает ожидание ответа, но не откатывает уже подтверждённую операцию корзины. При неизвестном исходе сначала прочитайте proposal/cart; не создавайте новую команду автоматически.

## Файлы

Поддерживаются XLSX, DOCX, PDF, JPEG, PNG, UTF-8 TXT/CSV. Старые XLS/DOC, архивы, исполняемые файлы и зашифрованные документы не принимаются.

Для загрузки установите рабочий ClamAV с актуальной базой и укажите его исполняемый файл:

```dotenv
UPLOADS_ENABLED=true
SCANNER_COMMAND=["C:/Program Files/ClamAV/clamscan.exe","--no-summary"]
```

Загрузка: POST `/api/v1/assets/upload?filename=spec.xlsx`, тело — исходные байты файла, Content-Type — реальный MIME. Не multipart и не JSON/base64. В ответе AssetView с id/status/warnings. GET `/api/v1/assets/{id}` читает статус, POST `/api/v1/assets/{id}/delete` удаляет файл. В чате передавайте только выданные asset_ids своей сессии.

При неработающем антивирусе файл остаётся quarantined: его нельзя разобрать или отправить модели. Подмена антивируса заглушкой допустима только внутри тестов, в конфигурации приложения так делать нельзя.

| Ограничение | Значение |
| --- | --- |
| Один файл | 10 МиБ |
| Вложения в turn | 3 |
| Файлы одной сессии | 20 / 100 МиБ исходных файлов |
| Общее хранилище исходных файлов | 1 ГиБ |
| Извлекаемый текст | 40 000 символов на файл |
| Таблицы | Ограниченное число строк/столбцов; сокращение явно отмечается |
| PDF с текстом | До 20 страниц |
| PDF без извлекаемого текста | До 4 отрисованных страниц для vision |
| Изображения для одного запроса модели | До 4; длинная сторона до 2000 px |
| Исходное изображение | До 20 мегапикселей |

Сокращение даёт partial/warnings, а не ложное «весь файл прочитан». Страницы PDF без текста отрисовываются для vision в пределах лимита; изображения на страницах с извлекаемым текстом могут требовать отдельного фото/анализа. Наличие читаемой маркировки не доказывает совместимость оборудования. Если детализация недостаточна, нужны более чёткое фото или артикул.

Парсеры запускаются отдельным процессом с таймаутом, очищенным окружением и ограничениями форматов. Это **не полноценная ОС-песочница**: для публичного приёма недоверенных документов нужен отдельный контейнер с запретом сети и лимитами памяти/CPU. Worker удаляет истёкшие файлы и осиротевшие blobs; при остановленном worker cleanup не выполняется.

## Границы модели и данных

Модель выдаёт строгий JSON намерения/поисковых запросов/выбора, а не произвольный клиентский ответ. Product IDs проверяются по полученным кандидатам. Цены, остатки, характеристики, сертификаты, условия и результат корзины формируются сервером. Prompt запрещает инструкции из description, истории, файлов и изображений. У модели нет инструмента подтверждения корзины, исполнения кода, произвольного URL или SQL.

Источник каталога остаётся отдельным портом. В репозитории доступна синтетическая выборка. Подключение всего реального каталога EKT, обновления цены/остатка, PostgreSQL и интеграция реальной корзины — отдельная работа по данным. Пустая выдача в частичном каталоге не означает отсутствие товара в магазине. Полноту каталога и нулевую вероятность ошибки модели обещать нельзя.

Автоматические аналоги разрешены только для категорий с заданными обязательными параметрами. Недостающие данные, конфликт и снижение критичных характеристик блокируют рекомендацию. Сертификаты не выдумываются; отсутствие ссылки сообщается явно. Условия переведены на kk/en с проверкой версии исходного текста; изменённый источник выводится в оригинале с предупреждением.

Платёжные реквизиты и API-ключи не запрашиваются. Очевидные платёжные номера/секреты в текстовом запросе отклоняются до сохранения; это не универсальный DLP для всех файлов и изображений. Клиенту нужно показывать предупреждение не загружать платёжные/лишние персональные данные. Согласие на передачу не заменяет политику минимизации данных.

## Расходы и отказоустойчивость

До каждого OpenAI-вызова резервируется верхняя оценка токенов в SQLite с суточной квотой сайта и сессии. Значения: `LLM_SESSION_DAILY_TOKENS`, `LLM_SITE_DAILY_TOKENS`. Это токенные, не денежные лимиты; отдельный бюджет проекта задайте в OpenAI. При timeout резерв сохраняется, SDK-повторов нет. Call ID связан с turn; повтор не делает новый платный вызов. После серии ошибок действует временный circuit breaker процесса.

Сетевой timeout модели — 12 секунд по умолчанию, worker — 25 секунд. «Единицы секунд» остаётся целью для измерений на реальном ключе; локальные mock-тесты её не подтверждают. При недоступности модели возвращается ответ из доступных серверных данных с предупреждением.

## Приёмка

Автотесты покрывают пять сценариев ТЗ, изоляцию сессий/диалогов, повторные подтверждения, неизвестный товар модели, prompt injection в поддельном ответе, смену языка, разрешение на внешнюю обработку, квоты модели, таймауты, форматы/карантин/удаление файлов. Запуск: `.venv/Scripts/python.exe -m pytest`.

Реальные платные запросы не выполнялись. Для завершения внешней приёмки нужны: ключ OpenAI с доступом к модели, настроенный настоящий scanner, каталог/API от участника 1 и проверка интерфейса с новыми DTO. Дополнительные функции ТЗ — авторизованная долговременная история, сопутствующие товары, интеграция менеджера — не считаются готовыми только по наличию session history или ссылки «Контакты».

Официальные источники реализации OpenAI: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [Images and vision](https://developers.openai.com/api/docs/guides/images-vision).
