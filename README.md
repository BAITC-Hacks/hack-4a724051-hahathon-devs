# hack-4a724051-hahathon-devs

Команда Hahathon Devs, HACKALEM AI 2026.

Кейс: ИИ-ассистент для чата на сайте ekt.kz (ТОО "Электрокомплект").

## Что делаем

Чат-ассистент для интернет-магазина электротехники ekt.kz. Клиент пишет в чат вопрос про товар и получает ответ сразу, без звонка менеджеру.

Ассистент должен уметь:

- рассказать про товар: характеристики, сертификаты, цена
- проверить наличие и остатки по складам
- подобрать аналог, если товара нет, и объяснить почему предложен именно он
- ответить про условия покупки: оплата, доставка, минимальная партия
- добавить товар в корзину, но только после того как клиент явно подтвердил
- дать ссылку на корзину

Отдельно хотим поддержать вложения (фото, Excel, Word, PDF), чтобы клиент мог скинуть спецификацию и получить подбор по списку.

## Обязательные требования кейса

- [ ] Наличие, характеристики и сертификат по артикулу
- [ ] Аналоги для позиций с нулевым остатком, с обоснованием
- [ ] Ответы на вопросы об условиях покупки
- [ ] Корзина меняется только после явного подтверждения, количество не больше остатка
- [ ] Ссылка на актуальную корзину после добавления

Опционально: казахский язык, сопутствующие товары, история диалога, передача вопроса менеджеру.

## Данные

Используем тестовый API каталога ekt.kz (basic auth, доступ выдал партнер, в репозиторий не кладем).

`GET /api/products?page=N` отдает список товаров по 20 штук на страницу. Поля: `id`, `name`, `article`, `price`, `image`, `url`, `url_api_detail`, `offers`.

`GET /api/products/detail?id=ID` отдает карточку товара. Дополнительно есть `description` (описание и характеристики текстом), `quantity` (общий остаток) и `stores` (остаток по каждому складу и городу).

Что заметили при разборе:

- отдельного поля с категорией нет, ее можно достать из `url`
- характеристики лежат внутри `description` обычным текстом, их придется разбирать
- API корзины нет, корзину делаем на своей стороне
- условий оплаты и доставки в API нет, соберем их отдельно

## Архитектура (план)

```
виджет чата на сайте
        |
     backend  ----  LLM
        |
  +-----+------+
  |            |
каталог     корзина
(API ekt.kz) (своя, по сессии)
```

Backend хранит сессию диалога, ходит в каталог за актуальной ценой и остатком и передает LLM только проверенные данные. Цену и наличие модель не придумывает, берет из API. Любое изменение корзины идет через отдельный шаг подтверждения.

Стек и детали допишем по ходу работы.

## Данные для демо

Каталог в репозитории синтетический: `data/synthetic/ekt_products.json`. Формат тот же, что у `/api/products/detail`, но товары, артикулы, цены и остатки придуманы. Условия покупки собраны с публичных страниц ekt.kz в `data/curated/purchase_terms.json`, у каждой темы указан источник.

## Логика ассистента

Код в `backend/app/modules`:

- `catalog` модель товара и правила проверки данных (продающие склады, противоречия в характеристиках)
- `search` поиск по артикулу и тексту, подбор аналогов с объяснением
- `knowledge` условия покупки
- `actions` предложение в корзину и подтверждение
- `assistant` Claude, инструменты, промпт, проверка ответа
- `chat` один ход диалога

Как это стыкуется с API и БД, описано в [docs/contracts.md](docs/contracts.md).
